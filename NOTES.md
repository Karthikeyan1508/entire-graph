## SUMMARY — real shapes, for whoever writes `tower/entire_adapter.py` (read this before parsing)

**Command syntax — every spec guess was wrong in the same way: no bare `--json`, and `def`'s symbol
selector is positional, not a flag.**

| Function | Spec guess | Real command |
|---|---|---|
| capabilities | `entire graph capabilities` | same, but needs `--json` (not bare) |
| search | `entire graph search --query "..." --format json --top-k 8` | correct as guessed, add `--repo .` |
| def | `entire graph def --symbol <file>:<line> --json` | `entire graph def <file>:<line> --repo . --format json` — **positional arg, no `--symbol` flag on `def`**, and `--format json` not `--json` |
| impact | `entire graph impact --symbol NAME --depth 2 --json` | `entire graph impact --symbol <file>:<line> --repo . --depth 2 --format json` — `--symbol` flag is correct here (unlike `def`), but still `--format json` not `--json` |
| checkpoint list | `entire checkpoint list --json` | exactly as guessed |

**`def` returns line ranges: YES.** Top-level key is `declarations` (an array, even for one match),
each with `file_path`, `start_line`, `end_line` (plus `fields_total`/`methods_total`/etc. — all 0 for
a plain function). So `SymbolRef.line_start/line_end` map directly to `start_line`/`end_line`.

**`impact` reports hop distance as `depth` on each relation entry, not a top-level "hops" field.**
Shape: `{focus: {id,name,file_path,start_line,end_line,...}, callers: {total,direct,transitive,entries:[{endpoint:{id,name,file_path,start_line,end_line,...}, relation, direction, depth, call_site:{file_path,line}}]}, callees: {...same entry shape, depth always 1}, type_consumers: {...}, data_flows:{...}, co_changes:{entries:[{endpoint:{...,kind:"file"}, relation:"FILE_CHANGES_WITH", detail}] — no depth field}, siblings:{...}}`.
So `impact_set(symbol, depth=2)` = read `callers.entries[].depth` (1 or 2) as the hop count for each
caller endpoint; `callees.entries` and `type_consumers.entries` carry `depth:1` always (impact only
transitively expands callers, not callees). `co_changes` entries have no `depth` — treat as file-level
prior evidence, not a lease hop.

**Symbol identity: Entire already has a stable compound ID — use it, don't reinvent `path::name`.**
Every endpoint carries `id` like `local/entire-graph:Go:internal/sem/search.go:function:SearchRepository`
(format `local/<repo>:<lang>:<path>:<kind>:<name>`). `search` results carry the same thing as
`symbol_id` (e.g. `local/entire-graph:Go:internal/sem/search.go:function:searchRepository`). Spec
§3.1's `mux.go::Router.Match` convention is superseded — `tower/core.py` should key leases on
Entire's own `id`/`symbol_id`, not a hand-rolled one. (File pseudo-symbols for unresolved targets
still need a fallback — Entire has no equivalent for "new file, no symbol yet".)

**`search` result fields:** `results[]` has `rank, score, file_path, start_line, end_line, focus_line,
snippet_start_line, snippet_end_line, symbol_start_line, symbol_end_line, language, kind, symbol_id,
symbol_name, qualified_name, signature, signals, snippet`. Two line-range pairs exist — `start_line/
end_line` is the reported (possibly-snippet) region, `symbol_start_line/symbol_end_line` is the full
enclosing symbol. **Use `symbol_start_line`/`symbol_end_line` for the lease row**, not `start_line`/
`end_line`, or a large function will lease only the few lines the ranker printed.

**`checkpoint list --json` fields:** flat array of `{checkpoint_id, session_id, date, message}`. No
separate "intent" field — `message` is the (truncated) prompt text. `session_intent()` per spec §4
was meant to come from `checkpoint explain <id> --short`, which recon did NOT run (not in the
requested command list) — still unverified, flag before relying on it.

**Latency — this is the load-bearing finding.** Working-tree queries are "always rebuilt, never
cached" (per AGENTS.md), and on this repo (~640-760 files) that rebuild is NOT "a few seconds":
`search` index_latency_ms=17599 (fast profile, Go-only completeness), `def` index_latency_ms=72732
(full profile, all-languages completeness), `impact` index_latency_ms=64422 (full profile). Every
plain `search`/`impact` call in working-tree mode independently pays this cost — it is not shared
across the two calls a single `file_flight()` makes. V2's flightplan hook assumes "a 5-second pause
is invisible"; on this machine two sequential cold working-tree calls cost ~90-140s, which blows past
any reasonable hook timeout (spec's own hook timeout is 60s in the settings.json snippet). Options to
raise with the user before writing `tower/core.py`: (a) `--head` mode (committed-tree, cached) instead
of working-tree default, accepting that uncommitted edits in the prompt's target files won't be seen;
(b) `entire graph index --repo . --head --profile full` once at session/demo start to warm the cache
and see if that actually helps working-tree calls (uncertain — index warms the committed-tree cache,
and working-tree mode is documented as never using it); (c) accept the latency and raise the hook
timeout, eating into the "invisible" framing. This needs a decision, not a workaround baked in quietly.

**Decided (user, post-recon):** option (a) + a warm cache. Every adapter call uses `--head --profile
full` (committed-tree only — uncommitted symbols are invisible to the lease, caught at file
granularity instead). `entire graph index --help` confirms the warm actually works: `index` prebuilds
the committed-tree cache, and a later `--head` query reuses it "when caching is enabled and they
resolve the same cache directory, profile, and ordered ignore/include inputs" against an unchanged
tree — `--head` on `index` itself is a documented no-op ("index is always HEAD-only"). So
`scripts/prewarm.sh` runs `entire graph index --repo . --profile full` once before a demo/session, and
the 17-73s cost above is paid once per commit, never per prompt.

**Noise side-effect of recon:** running `def`/`impact` after `search` had already written
`fixtures/search.json` (long single-line JSON) caused those later graph calls to flag `NOTES.md` and
`fixtures/*.json` as `E_MINIFIED` partial failures (long-line heuristic). Harmless for recon, but
`fixtures/` and `NOTES.md` should probably go in `.graphignore` before real lease-building searches
run against prompts, so they don't pollute real search results. Not done yet — flagging only.
